# Architecture

```
src/
  app/                    App Router: (site) public+account tree, (admin) staff tree, api/, metadata routes
  components/ui           Radix-based primitives (button, dialog, sheet, field, …)
  components/layout       Header, footer, mobile nav, skip link
  features/<feature>/     actions.ts (server actions), queries/, components/, schemas
  lib/
    supabase/             server/browser/admin clients, proxy session refresh
    auth/                 phone parsing, guards (requireUser/requireRole)
    providers/            provider registry + adapters (gov-il CKAN, commercial stubs, fixtures)
    security/             hashing, rate limit, request helpers
    analytics/            privacy-safe event tracking
supabase/migrations       numbered SQL (schema, functions, RLS, storage, hardening)
supabase/seed.sql         reference data (settings, policies, providers, catalog, geography)
tests/{unit,integration,e2e}
```

## Rendering
`cacheComponents` is disabled (classic model). `(site)` and `(admin)` layouts are `force-dynamic` because the header and guards are per-request. Images use `next/image`; signed Supabase URLs are cached on `listing_images.public_url` for active listings only.

## Authorization layers
1. `proxy.ts`: refreshes the Supabase session and redirects anonymous users away from `/account`/`/admin` (UX only).
2. Server: `requireUser`, `requireRole` (404 for non-staff), ownership checks in actions/route handlers.
3. Database: RLS + triggers (state machine, declaration, limits, locks, abuse flags). See `docs/DATABASE.md`.

## Staff roles
| Role | Rights |
|---|---|
| super_admin | everything, roles, settings, jobs |
| moderator | moderate listings, users, reports, appeals |
| support | read-only admin views |
| data_manager | providers, catalog, valuation settings |
| analyst | dashboards, audit log |

## Providers
`src/lib/providers/registry.ts` lists every provider with name, kind, version, configuration status, permission text and last success/error (persisted in `vehicle_data_sources`). Adapters: gov-il vehicles / history / recalls (CKAN `datastore_search`, configurable resource ids + field maps, timeouts), commercial valuation/history (not configured), SMS (Supabase), email, analytics. Fixtures only when `USE_DEV_FIXTURES=true` and not production.

## Valuation
`src/features/valuation/engine.ts`: pluggable sources. Internal source uses `comparable_listings` (same model, ±1 year, configurable window), returns IQR + median only above the minimum count, with confidence by sample size and explicit "asking prices, not transactions" labelling. Commercial source returns `not_configured`.

## Jobs
`/api/cron/expire` (Vercel Cron, `CRON_SECRET`): expires listings, applies retention to signals and analytics. Saved-search alerts and seller notifications are generated by DB triggers on status change.
